# LLM Benchmark

Бенчмарк для оценки ответов языковых моделей в задаче обучения английскому языку: генерация ответов преподавателя, автоматическая оценка по нескольким метрикам и формирование рейтинга моделей.

## Требования

- Python 3.10+
- API-ключ [OpenRouter](https://openrouter.ai/)
- ~1 ГБ свободного места на диске (локальные модели для оценки по критериям CEFR и Support)

## Установка

```bash
python -m venv .venv
source .venv/bin/activate   # Windows: .venv\Scripts\activate
pip install -r requirements.txt
```

## Запуск

Из корня проекта:

```bash
python -m run_benchmark
```

Скрипт задаёт вопросы в интерактивном режиме. При неверном вводе покажет ошибку и попросит повторить.

### Пропуск генерации

Если ответы моделей уже сохранены в `results/raw_outputs.csv`, можно пропустить этап генерации:

```
Skip generation and use existing raw_outputs.csv? (y/n):
> y
```

В этом режиме скрипт запрашивает только:

| Параметр | Описание |
|----------|----------|
| OpenRouter API key | Ключ для judge-модели (оценка Context и Scaffold) |
| Judge model | ID модели-судьи в OpenRouter, например `openai/gpt-oss-120b:free` |

### Полный прогон (генерация + оценка)

Ответьте `n` на вопрос о пропуске генерации. Дополнительно потребуется:

| Параметр | Описание |
|----------|----------|
| Models | Одна или несколько моделей OpenRouter через запятую, например `openai/gpt-4o-mini, anthropic/claude-3.5-sonnet` |
| Judge model | Модель для LLM-оценки (Context Integration, Scaffold) |
| Prompt | `1`, `2`, `3` или `all` — какой системный промпт использовать для генерации |
| CEFR level | `A1`–`C2` или `all` — подмножество тестового датасета |

**Промпты:**

- **1** — развёрнутый промпт с примерами и описанием уровней CEFR
- **2** — сокращённый промпт с правилами для учителя
- **3** — минимальный промпт («ответь ученику»)
- **all** — прогон по промптам 1, 2 и 3

Промпт 4 (коррекция фразы) генерируется **всегда**, независимо от выбора.

## Что происходит при запуске

1. **Подготовка моделей** — локальные DistilBERT-модели для метрик CEFR и Support. Если их нет, архивы скачиваются с Google Drive автоматически (см. ссылки ниже).
2. **Генерация** *(если не пропущена)* — для каждой строки датасета и каждой модели отправляются запросы в OpenRouter. Результаты сохраняются в `results/raw_outputs.csv`.
3. **Оценка** — для каждого ответа считаются метрики: CEFR, Support, Context Integration, Scaffold, Correction (exact match).
4. **Агрегация** — итоговые метрики и рейтинг.

Во время работы отображается прогресс генерации, оценки и загрузки моделей.

## Результаты

Файлы сохраняются в каталог `results/`:

| Файл | Содержимое |
|------|------------|
| `raw_outputs.csv` | Сырые ответы моделей |
| `detailed_results.csv` | Оценка по каждой строке |
| `evaluation_results.csv` | Агрегированные метрики по модели и промпту |
| `leaderboard.csv` | Рейтинг моделей по среднему `total` |

## Датасет

Тестовые реплики лежат в `benchmark/test_utterances/` — CSV с разделителем `;` (колонки: реплика ученика, CEFR, эталон, тип ошибки).

## Локальные модели оценки

При первом запуске модели скачиваются автоматически. При необходимости их можно загрузить вручную:

**Модель для оценки CEFR:**  
https://drive.google.com/file/d/10KafaU6K6brSFpCfmyXIgJiUvjm9ySY4/view?usp=sharing

**Модель для оценки Support:**  
https://drive.google.com/file/d/1HIF9_2Dkp1oiGmwVUazA6Ea5ZmJBNG7a/view?usp=sharing

Архивы положите в `benchmark/models/` с именами:

- `UPD_cefr_model_extended_dataset.zip`
- `UPD_support_model.zip`

Скрипт распакует их в подкаталоги при запуске.

## Структура проекта

```
llm_evaluation/
├── run_benchmark.py          # Точка входа
├── benchmark/
│   ├── prompts.py            # Промпты для генерации и judge-оценки
│   ├── inference.py          # Клиент OpenRouter
│   ├── evaluator.py          # Локальные модели + LLM-judge
│   ├── metrics.py            # Расчёт метрик
│   ├── model_assets.py       # Загрузка моделей с Google Drive
│   └── test_utterances/      # Тестовый датасет (A1–C2)
└── results/                  # Выходные CSV
```
